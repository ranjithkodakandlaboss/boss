## AUD-07: Unapproved Assumptions and Contradictions

### Evidence and corrections

#### AUD-07a: Gapless invoice numbering presented as statutory requirement

**v1.0 claim**: Gapless sequential numbering is a statutory requirement.
**Actual status**: Gapless numbering is a best practice strongly recommended for GST audit purposes and is mandated by GSTN for e-invoice series. It is not explicitly mandated in the CGST Rules for all invoices, but violations invite scrutiny during assessment.

**Correction**: Reframed as "GSTN-recommended and audit-prudent" rather than a universal statutory mandate. The technical implementation (pessimistic lock on `invoice_sequence_counters`) is retained as the correct approach. FD-39 (IRN decision) is the actual statutory gate.

#### AUD-07b: Desirable items automatically pre-approved for deferral

**v1.0 claim**: "All P2-DESIRABLE items pre-approved for deferral" appears in `CAPACITY_AND_CRITICAL_PATH.md`.
**Actual status**: No explicit founder approval was recorded for specific item deferral. Blanket pre-approval is not in the discovery pack.

**Correction**: `CAPACITY_AND_CRITICAL_PATH.md` v1.1 lists specific P2 items with rationale. Deferral is flagged for founder confirmation, not assumed approved.

#### AUD-07c: In-process inspections contradictory classification

**v1.0 state**: `12_DEFINITION_OF_DONE.md` listed in-process inspections as Must-Have; `other-prototype-domains.md` listed them as Desirable Pilot.

**Correction**: Classified as P2-DESIRABLE. Final inspection (before dispatch) is P1-MUST. Stage-gate inspections are P2-DESIRABLE unless customer pilot requires them. Customer feedback (Nov 15) explicitly requested configurable stage inspections — awaiting transcript for exact wording before elevating to P1.

#### AUD-07d: WhatsApp scope creep

**v1.0 state**: Some WhatsApp stories included notification broadcasts beyond the 4 confirmed workflows.

**Correction**: WhatsApp limited strictly to 4 confirmed workflows per FD-41 through FD-44. Any expansion requires explicit founder decision.

#### AUD-07e: Customer Group hierarchy inconsistency

**v1.0 state**: `customer-hierarchy.md` defined the hierarchy correctly, but the physical schema did not include a `customer_groups` table.

**Correction**: `customer_groups` table added to physical schema V002. `tenant_registry` FK to `customer_groups` added.

#### AUD-07f: Platform Admin parallelism error

**v1.0 state**: Platform Admin stories were shown as parallelisable with VS-02 (backend foundation), but VS-02 creates the shared auth infrastructure Platform Admin depends on.

**Correction**: Platform Admin EPIC-03/VS-16 explicitly depends on VS-02 completion. Dependency register updated.

#### AUD-07g: Prototype parity described as verified

**v1.0 state**: Prototype parity matrix used `PROTOTYPE_SHA_TO_BE_RECORDED` placeholder but classified screens as P1/P2/P3 as if verified.

**Correction**: All parity classifications in `07_PROTOTYPE_PARITY_MATRIX.md` explicitly marked UNVERIFIED pending repository access and SHA recording on Day 1.
